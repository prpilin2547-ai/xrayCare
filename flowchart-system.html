Entity Details

Hospital (Hospitals)
RID (PK, int, auto-increment)
Name (text) - ชื่อโรงพยาบาล
Code (text) - รหัสโรงพยาบาล
Machine (Machines)
RID (PK), HospitalId (FK)
Machine_name - ชื่อเครื่อง
Room - ห้อง
Register_date - วันที่ลงทะเบียน
Caretaker - ผู้ดูแล
UserAccount (Users)
RID (PK), HospitalId (FK)
Username (unique per hospital)
Password, Position
IsSuperAdmin (boolean)
ChecklistRecord (ChecklistRecords)
RID (PK), HospitalId (FK)
FormType - F1_F2, F10, F3_F6, F7_F8, F9, F11, F12, F13
MachineName, Room, CheckDate
Tester - ผู้ทดสอบ
JsonData - ข้อมูลผลตรวจ JSON
RepairRequest (RepairRequests)
RID (PK), HospitalId (FK)
Equipment, Room, RequestDate
ReporterName - ผู้แจ้งซ่อม
Detail, Remarks, StatusText
ImageData - รูปภาพ Base64
ScheduleConfig (ScheduleConfigs)
RID (PK), HospitalId (FK)
StartDate - วันเริ่มต้น
FrequencyType - 1m, 3m, 6m
Description - รายละเอียด
FormTypes - JSON array เช่น ["F10","F12"]
Relationship Labels (ความหมายของป้ายบนเส้นเชื่อม)
1-N Hospital มีข้อมูลลูกหลายรายการ (One-to-Many)
triggers ScheduleConfig กำหนดเวลาตรวจให้ ChecklistRecord
checked Machine ถูกตรวจสอบ บันทึกใน ChecklistRecord
repaired Machine ถูกแจ้งซ่อมผ่าน RepairRequest
tested UserAccount เป็นผู้ทดสอบ บันทึกใน ChecklistRecord
reported UserAccount เป็นผู้แจ้งซ่อม สร้าง RepairRequest
สัญลักษณ์: ||--o{ = One-to-Many (1 ต่อ หลาย) | PK = Primary Key | FK = Foreign Key
หมายเหตุ: ทุก Entity สืบทอด RID (Primary Key, auto-increment) จาก BaseTable | HospitalId เป็น Foreign Key อ้างอิงไปยัง Hospital.RID | ChecklistRecord เชื่อมกับ Machine ผ่าน MachineName + Room (denormalized) | Unique constraint: UserAccount(HospitalId, Username) | Database: PostgreSQL via Entity Framework Core + Npgsql

Context Diagram

แผนภาพบริบทของระบบ xrayCare แสดงความสัมพันธ์ระหว่างระบบกับ External Entity ทั้งหมด

External Entities and Data Flows

SuperAdmin
Input: Login, จัดการผู้ใช้ทุก รพ., จัดการโรงพยาบาล, ตั้งค่าระบบ
Output: ผลจัดการ User/Hospital, Admin Analytics, รายงานภาพรวม
Admin
Input: Login, จัดการผู้ใช้เฉพาะ รพ.
Output: ผลจัดการ User, Admin Analytics เฉพาะ รพ.
Radiological Technologist
Input: Login, บันทึกผลตรวจ F1-F13, จัดการเครื่อง, แจ้งซ่อม, PM Schedule, แนบรูปภาพ
Output: ผลตรวจ Pass/Fail, สถานะเครื่อง, Repair อัตโนมัติ, แจ้งเตือน, Analytics, Export PDF
Engineer
Input: Login, อัปเดตสถานะซ่อม (Pending/In Progress/Completed)
Output: รายการแจ้งซ่อม, สถิติการซ่อม, Engineer Analytics
PostgreSQL Database
Input: CRUD operations ผ่าน REST API (Hospitals, Users, Machines, Checklists, Repairs, Schedules)
Output: ข้อมูลทั้งหมดของระบบ, Notifications (คำนวณจาก ScheduleConfigs)
Architecture: Vue 3 SPA (port 5173) → Vite Proxy → ASP.NET Core API (port 8001) → PostgreSQL via EF Core + Npgsql | Headers: X-User-Id, X-Hospital-Id | CORS: localhost:5173
